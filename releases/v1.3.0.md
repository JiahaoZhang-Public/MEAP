# v1.3.0

Date (UTC): 2026-02-21
Tag: `v1.3.0`

## Summary

- Promote `AttributionModel` to primary public entrypoint.
- Keep legacy high-level APIs as compatibility wrappers with deprecation warnings.
- Add prepared-input-first example and docs alignment for V2 migration path.
- Add route/graph/hook matrix validation script for text and multimodal models.

## Breaking Changes

- None in this release (soft migration).

## Features

- New object API:
  - `AttributionModel.from_pretrained(...)`
  - `AttributionModel.from_model(...)`
  - `build_graph(...)`, `validate_batches(...)`, `attribute(...)`, `evaluate_graph(...)`
- New public datatypes:
  - `RouteInfo`
  - `AttributionResult`
  - `PreparedInputLike`
- New task/metric helper module (`meap.tasking`) shared by old/new entrypoints.
- New route matrix script:
  - `scripts/route_graph_matrix.py`
  - optional attribution smoke per model: `--run-attribute-smoke`

## Fixes

- Consolidated task/metric contract checks to avoid divergence across APIs.
- Hardened prepared batch validation and nested mapping normalization paths.

## Compatibility

- `discover_circuit(...)` and `attribute_from_dataloader(...)` remain callable.
- Both now emit `DeprecationWarning` with migration hints to `AttributionModel`.

## Validation

- [x] `python scripts/release/release.py gate --clean-dist`
- [x] package artifacts built and checked (`build`, `twine check`)

## Known Limits

- Multimodal attribution remains language-trunk-centric in MVP.
- `ComponentSpec` is public contract only; hook-level filtering is deferred.

## Upgrade Notes

- Preferred path:
  - user prepares model inputs (`PreparedBatch` or equivalent nested tensor mapping)
  - `AttributionModel` handles route validation + attribution runtime
- Compatibility lane remains available for one release cycle before reevaluation.
