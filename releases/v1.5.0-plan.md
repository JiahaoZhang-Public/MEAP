# v1.5.0 Plan: Architecture Expansion + Backend Decoupling

Date (UTC): 2026-02-21
Status: Implemented

## Objective

Deliver v1.5.0 as a combined release with two aligned tracks:

1. Expand official text/multimodal architecture coverage.
2. Decouple `meap/backend` so architecture-specific logic lives in adapters.

Core contract remains unchanged:

1. `model -> language trunk/graph`
2. `prepared inputs -> attribution`

No public API contract break is planned for v1.5.0.

## Scope

### In scope

- Promote/add more architecture families into official tested coverage.
- Expand official text + multimodal model matrix and CI tiering.
- Refactor backend internals to reduce `HFLLMBackend` coupling.
- Move architecture-specific attention/MLP/projection/gradient semantics into adapter-owned code.
- Keep `meap.catalog`, `docs/docs/SUPPORTED_MODELS.md`, onboarding docs, and matrix defaults consistent.

### Out of scope

- New attribution methods.
- `Graph` topology or hook naming changes.
- Prepared-input public contract changes (`PreparedBatch` / tensor dict).
- ComponentSpec hook-filter implementation (still deferred).

## Workstream B: Backend Decoupling

## Current pain points

1. `HFLLMBackend` currently mixes routing, hook target building, projection math, and backward remapping.
2. Architecture differences are represented as backend-level branching (`ProjectionSpec(kind=...)` + runtime conditionals).
3. Adding new architecture variants risks repeated edits in central backend runtime.

## Target design

## 1) Stable Graph hook ABI

Keep Graph-facing hook names unchanged:
- `hook_embed`
- `blocks.{layer}.attn.hook_result`
- `blocks.{layer}.hook_q_input`
- `blocks.{layer}.hook_k_input`
- `blocks.{layer}.hook_v_input`
- `blocks.{layer}.hook_mlp_in`
- `blocks.{layer}.hook_mlp_out`
- `blocks.{last}.hook_resid_post`

## 2) Backend layering

Introduce internal layers:

1. `RouteResolver`
- resolve `model -> language_trunk_path -> adapter` with stable diagnostics.

2. `HookTargetCompiler`
- compile structural adapter resolution into hook targets without architecture math.

3. `ArchitectureOperators` (adapter-owned)
- attention projection forward replacement;
- attention gradient projection to q/k/v input heads;
- MLP/norm input-output replacement rules;
- optional GQA/MQA normalization behavior.

4. `HFLLMBackend` (thin orchestrator)
- handle device/dtype/input prep + hook registration lifecycle;
- delegate architecture math to adapter operators.

## 3) Adapter contract upgrade

Extend `ArchitectureAdapter` (with compatibility defaults):

1. Existing structural methods
- `resolve(...)`
- `attn_result_module(...)`
- `qkv_hook_modules(...)`

2. New operator descriptors
- `attention_operator(attn_module, backend_config) -> AttentionOperator`
- `mlp_operator(layer_module, backend_config) -> MlpOperator`
- `norm_operator(norm_module, backend_config) -> NormOperator`

3. Capability metadata
- fused qkv layout type
- interleaving policy
- grouped-query handling mode
- MLP/FFN mode metadata

## Unified test strategy (v1.5.0)

## 1) Route + graph/hook verification

```bash
python scripts/route_graph_matrix.py \
  --text-models <comma-separated> \
  --multimodal-models <comma-separated> \
  --run-attribute-smoke \
  --device cpu \
  --dtype float32 \
  --output reports/route_graph_matrix_v1_5.json
```

Pass criteria:
- route resolved (`adapter_name`, `language_trunk_path` non-empty)
- graph build success (`n_forward`, `n_backward`, `n_edges_total` > 0)
- hook coverage `missing_count == 0`
- smoke attribution pass

## 2) Text parity verification

```bash
python scripts/test_text_vendor_parity.py \
  --models <text-models> \
  --methods EAP,EAP-IG-inputs,clean-corrupted,EAP-IG-activations \
  --strict \
  --output reports/text_vendor_parity_v1_5.json
```

Pass criteria (strict):
- `max_abs <= 1e-3`
- `cosine >= 0.995`
- `top-k overlap >= 0.90`

## 3) Smoke matrix regression

```bash
python scripts/smoke_hf_matrix.py \
  --text-models <text-pr-tier> \
  --multimodal-models <mm-pr-tier> \
  --device cpu \
  --dtype float32 \
  --output reports/smoke_hf_matrix_v1_5.json
```

## 4) Stage gate

```bash
python scripts/test_stage_matrix.py --strict --output reports/stage_matrix_v1_5.json
```

## 5) Quality gates

```bash
ruff check meap tests scripts
pytest -q
```

## Acceptance criteria for v1.5.0

1. At least two additional architecture families are validated and documented (`falcon_like`, `gemma_like`, `phi_like`).
2. Official model catalog includes expanded text + multimodal set.
3. `HFLLMBackend` no longer owns architecture-specific projection/gradient branching logic.
4. Official adapters own architecture semantics via operator implementations.
5. Graph hook ABI remains unchanged and matrix checks pass.
6. No breaking change in public API surface.

## Risks and mitigations

1. Model access/auth restrictions
- Mitigation: split auth-gated models into nightly/manual tier; keep open models in PR tier.

2. CPU runtime cost growth
- Mitigation: keep PR tier small/light; move heavy models to nightly.

3. Adapter false positives on `match(...)`
- Mitigation: enforce registry diagnostics + explicit required module checks in tests.

4. Refactor semantic drift in attribution behavior
- Mitigation: run parity/smoke matrix before and after decoupling; add contract/ABI tests.

5. Adapter capability boundaries unclear in first pass
- Mitigation: codify capability metadata in adapter contract and enforce with tests.
